# Поиск книг — React SPA

Одностраничное приложение на **React** для поиска книг по названию или ISBN через публичный сервис **Book Metadata Service**. Результаты отображаются в виде карточек с информацией о книгах.

В приложении реализованы поиск с автоподсказками, просмотр информации о найденных книгах, добавление книг в избранное, сохранение избранного в `localStorage` и отдельная страница для просмотра сохранённых книг.

## 1. Общая информация о проекте

### 1.1. Назначение приложения

**Поиск книг** — это SPA-приложение (Single Page Application), предназначенное для поиска книжных изданий по названию или ISBN.

Пользователь вводит поисковый запрос, после чего приложение отправляет его во внешний API и получает информацию о подходящих книгах.

Найденные книги отображаются в виде отдельных карточек. Пользователь может просмотреть основные сведения об издании, прочитать описание и добавить понравившуюся книгу в избранное.

В приложении предусмотрены две страницы:

- Главная страница — поиск книг и просмотр результатов.
- Страница избранного — просмотр сохранённых книг и поиск среди них.

### 1.2. Исходная задача

Основная задача проекта — разработать SPA на React, которое получает информацию о книгах через публичный API Book Metadata Service и отображает результаты в удобном виде.

Приложение должно позволять:

1. Вводить название книги или ISBN.
2. Запускать поиск кнопкой или клавишей Enter.
3. Не отправлять пустые поисковые запросы.
4. Показывать состояние загрузки.
5. Обрабатывать ошибки API.
6. Отображать сообщение, если книги не найдены.
7. Показывать найденные книги в виде карточек.
8. Выводить обложку, название, автора, год издания, ISBN и описание.
9. Предлагать автоподсказки при вводе названия книги.
10. Добавление в избранное и удаление из него книги.

### 1.3. Принцип работы

Приложение не содержит собственной базы данных с каталогом книг. Информация получается из внешнего сервиса Book Metadata Service.

Избранные книги сохраняются отдельно в браузере пользователя с помощью `localStorage`.

Таким образом, используются два разных источника данных:

|         Данные             |        Источник       |
|Результаты поиска           |Book Metadata Service  |
|Автоподсказки               |Book Metadata Service  |
|Сохранённые книги           |`localStorage` браузера|
|Текущее состояние интерфейса|React state            |

## 2. Основные возможности

### 2.1. Поиск книг

Пользователь может выполнить поиск по названию книги или ISBN через одно поле ввода.

Для отправки запроса предусмотрены два способа:

- Нажать кнопку «Найти».
- Нажать Enter после ввода текста.

Оба способа используют одну функцию обработки поиска.

Перед отправкой приложение удаляет пробелы в начале и конце запроса. Если после этого строка пустая, обращение к API не выполняется.

### 2.2. Автоподсказки

Во время ввода текста приложение может показывать подходящие книги.

Особенности реализации:

- Подсказки начинают запрашиваться, когда введено не менее трёх символов.
- Перед запросом выдерживается задержка 500 миллисекунд.
- Для подсказок запрашиваются только поля `Title` и `AuthorName`.
- Пользователь может выбрать подходящую книгу из списка.
- После выбора приложение запускает полноценный поиск по названию выбранной книги.
- Пользователь также может продолжить ввод своего запроса без выбора подсказки.

Автоподсказки реализованы через компонент `Autocomplete` из Material UI и пользовательский хук `useLogic`.

### 2.3. Карточки книг

Каждая найденная книга отображается отдельной карточкой.

Карточка может содержать:

- Обложку.
- Название.
- Автора.
- Год издания.
- ISBN.
- Издательство.
- Описание.

Если API не предоставил определённое поле, приложение показывает текстовую заглушку.

Если обложка отсутствует или не загружается, вместо неё отображается placeholder.

Длинное описание можно развернуть и свернуть.

### 2.4. Избранное

Пользователь может добавить книгу в избранное или удалить её оттуда.

Для этого в карточке предусмотрена кнопка с изображением сердца.

Если книга уже находится в избранном, кнопка меняет своё состояние.

При добавлении приложение проверяет, не сохранена ли такая книга ранее. Это позволяет избежать повторного добавления одной и той же записи.

### 2.5. Сохранение избранного

Избранные книги сохраняются в `localStorage`.

Благодаря этому данные остаются после перезагрузки страницы и повторного открытия приложения в том же браузере и в пределах того же origin.

Для хранения используется ключ:

```javascript
favoriteBooks
```

Данные записываются в формате JSON.

### 2.6. Отдельная страница избранного

Для просмотра сохранённых книг предусмотрен маршрут:

```text
/favorites
```

На этой странице пользователь может:

- Просмотреть все избранные книги.
- Удалить книгу из избранного.
- Найти книгу по названию.
- Найти книгу по автору.
- Найти книгу по ISBN.
- Вернуться на страницу поиска.

### 2.7. Обработка ошибок

Приложение предусматривает обработку различных ситуаций:

- Превышение лимита запросов API — HTTP 429.
- Другие HTTP-ошибки.
- Отсутствие ответа от сервера.
- Ошибка подключения или сетевого запроса.
- Превышение времени ожидания запроса.
- Получение ответа в неожиданном формате.

При возникновении ошибки пользователь получает соответствующее сообщение.

### 3.1. React

React используется для построения пользовательского интерфейса из компонентов.

В проекте основными компонентами являются:

- `App` — корневой компонент приложения, отвечающий за маршрутизацию.
- `Main` — главная страница поиска книг и отображения результатов.
- `BookCard` — карточка одной книги.
- `Favorites` — страница избранного.

React позволяет обновлять интерфейс при изменении состояния, не выполняя ручные манипуляции с DOM.

Например, когда пользователь добавляет книгу в избранное, React получает новое значение состояния и обновляет соответствующую часть интерфейса.

### 3.2. JSX

JSX — это синтаксис, позволяющий описывать структуру интерфейса внутри JavaScript.

Пример из проекта:

```jsx
<Typography variant="h3" component="h1">
    Поиск книжечек
</Typography>
```

Вместо отдельного HTML-файла для каждого компонента его разметка располагается непосредственно в JSX.

JSX преобразуется инструментами сборки в обычные JavaScript-вызовы, которые React использует для создания интерфейса.

### 3.3. React Hooks

Hooks — специальные функции React, которые позволяют функциональным компонентам работать с состоянием и другими возможностями React.

В проекте используются:

1. **`useState`**

Хранит состояние компонента.
Например:
```javascript
const [loading, setLoading] = useState(false);
```
Здесь:
- `loading` — текущее значение состояния.
- `setLoading` — функция изменения состояния.
- `false` — начальное значение.
При изменении состояния React обновляет интерфейс.

2. **`useEffect`**

Позволяет выполнять побочные эффекты после рендеринга компонента.
В проекте используется для:
- Получения автоподсказок после изменения строки поиска.
- Сохранения избранного в `localStorage`.
Пример:
```javascript
useEffect(() => {
    localStorage.setItem(
        "favoriteBooks",
        JSON.stringify(favorites)
    );
}, [favorites]);
```
Этот эффект запускается при изменении `favorites`.

**Почему используются пользовательские хуки?**

Логика поиска и работы с избранным вынесена в отдельные файлы:
```text
src/hooks/useLogic.js
src/hooks/useFavorite.js
```
Это позволяет не размещать всю бизнес-логику внутри компонентов интерфейса.

### 3.4. React Router DOM

React Router DOM используется для навигации между двумя страницами:

```text
/           — поиск книг
/favorites  — избранное
```

При переходе между этими страницами не требуется полностью перезагружать сайт. Маршрутизацией управляет React Router.

### 3.5. Material UI

Material UI — библиотека готовых компонентов для React.

В проекте используются, например:

- `Container` — ограничивает ширину содержимого.
- `Box` — универсальный контейнер для группировки элементов.
- `Typography` — отображает текст и заголовки.
- `TextField` — поле ввода.
- `Autocomplete` — компонент автоподсказок.
- `Button` — кнопки.
- `Alert` — информационные сообщения и ошибки.
- `CircularProgress` — индикатор загрузки.
- `Card` — карточка книги.
- `CardContent` — содержимое карточки.
- `CardMedia` — изображение обложки.
- `IconButton` — кнопка добавления или удаления из избранного.

Material UI отвечает за готовые элементы интерфейса, а CSS — за дополнительное расположение и оформление.

### 3.6. Axios

Axios — библиотека для выполнения HTTP-запросов.

В проекте она используется для обращения к Book Metadata Service.

Пример:
```javascript
const response = await axios.get(API_URL, {
    params,
    timeout: REQUEST_TIMEOUT_MS,
});
```
Axios самостоятельно формирует URL с query-параметрами из объекта `params`, отправляет GET-запрос и возвращает объект ответа.

В отличие от встроенного Fetch API, Axios автоматически отклоняет Promise для HTTP-статусов, которые не относятся к успешным ответам. Это позволяет обрабатывать HTTP-ошибки в блоке `catch`.

### 3.7. Vite

Vite используется как инструмент разработки и сборки.

Он выполняет две основные задачи:

1. Запускает локальный сервер разработки.
2. Собирает оптимизированную версию приложения для публикации.

Команды запуска находятся в `package.json`.

### 3.8. Vitest и React Testing Library

Vitest используется для автоматизированного тестирования.

React Testing Library предоставляет функцию `renderHook`, позволяющую запускать и проверять пользовательские React-хуки без необходимости создавать для каждого теста полноценную страницу.

`jsdom` предоставляет имитацию браузерного окружения, необходимую, например, для работы с `localStorage` в тестах.

### 3.9. ESLint

ESLint анализирует JavaScript и JSX-код и помогает находить проблемы, связанные с синтаксисом и правилами написания кода.

В проекте он используется через команду:
```powershell
npm run lint
```

```text

├── constants.js
└── searchBooks.js
```

`constants.js` хранит адрес сервиса и время ожидания ответа.

`searchBooks.js` содержит функцию, которая:

1. Подготавливает поисковый запрос.
2. Формирует параметры запроса.
3. Отправляет GET-запрос через Axios.
4. Обрабатывает сетевые и HTTP-ошибки.
5. Проверяет формат полученных данных.
6. Возвращает массив найденных книг.

Такой подход отделяет сетевую логику от компонентов интерфейса.

В `src/assets/` находятся статические ресурсы проекта. Например, в `index.html` используется файл `dota.svg` в качестве favicon.

### 5.1. Разделение ответственности

Каждая часть приложения выполняет свою задачу.

**App.jsx**
Отвечает за маршрутизацию приложения.
Содержит компонент `Routes` и два маршрута: `/` для главной страницы и `/favorites` для страницы избранного. Подключает соответствующие компоненты `Main` и `Favorites`.

**Main.jsx**
Отвечает за главную страницу поиска.
Связывает пользовательский хук `useLogic` с интерфейсом, управляет автоподсказками, выбором книг и отображением результатов через `BookCard`.

**useLogic.js**
Хранит состояние поиска и выполняет действия, связанные с поисковым запросом.

**searchBooks.js**
Изолирует сетевую логику и взаимодействие с внешним API.

**useFavorite.js**
Управляет добавлением, удалением, проверкой и сохранением избранных книг.

**Favorites.jsx**
Отображает сохранённые книги, выполняет фильтрацию и позволяет удалять записи.

**bookCard.jsx**
Отвечает за отображение одной книги независимо от того, где она показывается — в результатах поиска или на странице избранного.

### 5.2. Почему логика вынесена в хуки

После рефакторинга `App.jsx` больше не содержит основную логику поиска. Он отвечает только за маршрутизацию между страницами.

Функциональность главной страницы находится в `Main.jsx`, а логика поиска и автоподсказок по-прежнему вынесена в `useLogic.js`.

Такое разделение позволяет не перегружать корневой компонент приложения и упрощает дальнейшее добавление новых страниц.

Если разместить все операции непосредственно в `App.jsx`, компонент станет перегруженным.

Например, в одном файле пришлось бы одновременно:

- хранить строку поиска;
- выполнять запросы к API;
- управлять автоподсказками;
- обрабатывать ошибки;
- сохранять избранное;
- проверять уникальность книг;
- формировать карточки.

В текущей архитектуре большая часть логики разделена на независимые части.

Это упрощает понимание кода и позволяет отдельно проверять хуки с помощью тестов.

## 6. Как работает приложение

### 6.1. Запуск приложения

После открытия сайта браузер загружает `index.html`.

Внутри документа находится элемент:

```html
<div id="root"></div>
```

Он используется React как точка монтирования интерфейса.

Затем загружается `src/main.jsx`, который создаёт корневой элемент React, оборачивает приложение в `StrictMode` и `BrowserRouter`, а также отображает компонент `App`.

Сама маршрутизация между страницами определяется уже внутри `App.jsx`.

### 6.2. Поиск книги

Последовательность поиска:

1. Пользователь открывает главную страницу.
2. Вводит название книги или ISBN.
3. Обработчик `handleInputChange`, переданный в свойство `onInputChange` компонента `Autocomplete`, обновляет поисковую строку через `setQuery`.
4. React обновляет состояние строки поиска.
5. Пользователь нажимает кнопку «Найти» или Enter.
6. Событие отправки формы вызывает `handleSearch`.
7. Хук проверяет поисковую строку.
8. Если строка пустая, сетевой запрос не выполняется.
9. Если запрос корректный, включается состояние загрузки.
10. Вызывается функция `searchBooks`.
11. `searchBooks` отправляет GET-запрос через Axios.
12. API возвращает массив книг или HTTP-ошибку.
13. При успешном ответе массив сохраняется в состоянии `books`.
14. React обновляет интерфейс и создаёт карточки через `BookCard`.

### 6.3. Отображение результатов

Для отображения списка используется метод `map`.

Пример:
```jsx
{books.map((book, index) => (
    <BookCard
        key={book.guid || book.ISBN || index}
        book={book}
        isFavorite={isFavorite(book)}
        onToggleFavorite={handleToggleFavorite}
    />
))}
```

- `books` — массив найденных книг.
- `map()` перебирает элементы массива.
- `book` — текущая книга.
- `index` — индекс элемента.
- `BookCard` — компонент, которому передаются данные.
- `key` — специальный идентификатор элемента списка для React.
- `book` — объект с данными одной книги.
- `isFavorite` — информация о том, находится ли книга в избранном.
- `onToggleFavorite` — функция переключения состояния избранного.

Для каждой записи API создаётся отдельная карточка.

### 6.4. Переход на страницу избранного

В верхней части главной страницы находится ссылка на:
```text
/favorites
```

React Router отображает страницу `Favorites.jsx`.

При открытии страницы хук `useFavorite` загружает ранее сохранённые данные из `localStorage`.

Если избранных книг нет, пользователь видит соответствующее информационное сообщение.

Если книги есть, они отображаются с помощью того же компонента `BookCard`.

## 8. Подробный разбор `useLogic.js`

Файл:

```text
src/hooks/useLogic.js
```

Этот пользовательский хук отвечает за основную логику поиска.

В нём находятся:

- Состояние поисковой строки.
- Массив найденных книг.
- Состояние загрузки.
- Информация об ошибке.
- Признак выполненного поиска.
- Массив автоподсказок.
- Состояние загрузки автоподсказок.
- Функция отправки поискового запроса.

### 8.1. Импорты

```javascript
import { useEffect, useState } from "react";
import { searchBooks } from "../api/searchBooks.js";
```

`useState` используется для хранения состояния React.

`useEffect` используется для выполнения побочного эффекта при изменении поисковой строки.

`searchBooks` импортируется из API-модуля и выполняет реальный запрос к внешнему сервису.

### 8.2. Создание функции хука

```javascript
export default function useLogic() {
```

Объявляется пользовательский хук `useLogic`.

Он вызывается внутри функционального React-компонента:

```javascript
const {
    query,
    setQuery,
    books,
    loading,
    error,
    searched,
    handleSearch,
    suggestions,
    suggestionsLoading,
} = useLogic();
```
Благодаря этому компонент получает необходимые значения и функции.

### 8.3. Состояние поискового запроса

```javascript
const [query, setQueryState] = useState("");
```

`query` хранит текст, который вводит пользователь.

Начальное значение — пустая строка.

`setQueryState` изменяет значение состояния.

При изменении `query` React выполняет повторный рендер компонента, а `useEffect` может запустить получение автоподсказок.

### 8.4. Состояние найденных книг

```javascript
const [books, setBooks] = useState([]);
```

`books` хранит массив найденных книг.

Начальное значение — пустой массив.

После успешного ответа API массив сохраняется через `setBooks`.

Затем главная страница перебирает массив и создаёт карточки.

### 8.5. Состояние загрузки

```javascript
const [loading, setLoading] = useState(false);
```

`loading` определяет, выполняется ли основной поиск.

Начальное значение — `false`, потому что при открытии страницы поиск ещё не выполнялся.

Во время запроса значение меняется на `true`.

После завершения запроса, независимо от результата, значение возвращается к `false`.

В интерфейсе это состояние используется для:

- отображения индикатора загрузки;
- отключения поля поиска;
- отключения кнопки отправки.

### 8.6. Состояние ошибки

```javascript
const [error, setError] = useState(null);
```

`error` хранит сообщение об ошибке.

Если ошибки нет, используется `null`.

Если запрос завершился ошибкой, в состояние записывается текстовое сообщение.

Главная страница отображает его с помощью компонента `Alert`.

### 8.7. Признак выполненного поиска

```javascript
const [searched, setSearched] = useState(false);
```

Это состояние позволяет отличить ситуацию, когда пользователь ещё не выполнял поиск, от ситуации, когда поиск уже выполнен, но результатов нет.

Например:

- `searched = false` — пользователь ещё не искал книги.
- `searched = true` и `books.length === 0` — поиск выполнен, но подходящих книг нет.
- `searched = true` и `books.length > 0` — книги найдены.

Без этого признака приложение могло бы показывать сообщение об отсутствии книг сразу после открытия страницы.

### 8.8. Состояние автоподсказок

```javascript
const [suggestions, setSuggestions] = useState([]);
const [suggestionsLoading, setSuggestionsLoading] = useState(false);
```

` suggestions` хранит массив книг, полученных для автоподсказок.

`suggestionsLoading` показывает, загружаются ли подсказки.

Это отдельные состояния от основного поиска.

Почему они разделены?

Автоподсказки и полноценный поиск выполняют разные запросы и имеют разные задачи.

Автоподсказки нужны для выбора подходящего варианта во время ввода.

Полноценный поиск нужен для получения результатов, которые будут показаны в основной части страницы.

### 8.9. Функция изменения запроса

```javascript
const setQuery = (value) => {
    setQueryState(value);
    setSuggestions([]);
    setSuggestionsLoading(false);
};
```

Функция `setQuery` выполняет три действия:

1. Сохраняет новое значение поисковой строки.
2. Очищает старые автоподсказки.
3. Сбрасывает состояние загрузки подсказок.

Это помогает не показывать устаревшие подсказки после изменения текста.

Здесь используется отдельная функция `setQuery`, которая оборачивает стандартную функцию `setQueryState`.

Она нужна не только для изменения строки, но и для дополнительного обновления связанных состояний.

### 8.10. Получение автоподсказок через useEffect

```javascript
useEffect(() => {
    const normalizedQuery = query.trim();

    if (normalizedQuery.length < 3) {
        return;
    }

    const controller = new AbortController();

    const timeoutId = setTimeout(async () => {
        setSuggestionsLoading(true);

        try {
            const result = await searchBooks(
                normalizedQuery,
                "Title,AuthorName",
                controller.signal
            );

            if (!controller.signal.aborted) {
                setSuggestions(result);
            }
        } catch (error) {
            if (controller.signal.aborted) {
                return;
            }

            setSuggestions([]);
            console.error("Ошибка получения подсказок:", error);
        } finally {
            if (!controller.signal.aborted) {
                setSuggestionsLoading(false);
            }
        }
    }, 500);

    return () => {
        controller.abort();
        clearTimeout(timeoutId);
    };
}, [query]);
```

Этот эффект запускается при изменении `query`.

После проверки минимальной длины создаётся объект `AbortController`.

Он используется для управления отменой HTTP-запроса. Через свойство `signal` контроллер передаёт сигнал в функцию `searchBooks`, а затем в Axios.

При изменении поисковой строки React выполняет очистку предыдущего эффекта. В этот момент вызывается `controller.abort()`, который отменяет предыдущий запрос, если он ещё выполняется.

Сначала вызывается:

```javascript
const normalizedQuery = query.trim();
```

`trim()` удаляет пробелы в начале и конце строки.

Затем проверяется длина строки:

```javascript
if (normalizedQuery.length < 3) {
    return;
}
```

Если введено меньше трёх символов, запрос подсказок не выполняется.

Это позволяет не обращаться к API после каждого символа в коротком запросе.

### 8.11. Задержка перед запросом

```javascript
const timeoutId = setTimeout(async () => {
    setSuggestionsLoading(true);

    // ...
}, 500);
```

`setTimeout` откладывает выполнение функции на 500 миллисекунд.

Это называется debounce-подходом или задержкой перед выполнением действия.

Например, пользователь вводит:

```text
Г
Га
Гар
Гарр
Гарри
```

Без задержки приложение могло бы выполнить несколько запросов подряд.

С задержкой в 500 миллисекунд приложение ждёт, пока пользователь немного остановится во вводе.

Если за это время пользователь продолжит печатать, предыдущий таймер будет очищен при очистке эффекта.

В результате уменьшается количество лишних обращений к API.

Если предыдущий таймер уже успел сработать и HTTP-запрос был отправлен, одной очистки `setTimeout` недостаточно. Поэтому дополнительно используется `AbortController`, который позволяет отменить уже начатый запрос через Axios.

### 8.12. Выполнение запроса подсказок

```javascript
const result = await searchBooks(
    normalizedQuery,
    "Title,AuthorName",
    controller.signal
);
```

Вызывается функция `searchBooks`.

Функции передаются три аргумента:

- `normalizedQuery` — поисковый текст.
- `"Title,AuthorName"` — список полей API, которые необходимы для подсказок.
- `controller.signal` — сигнал отмены HTTP-запроса.

Для автоподсказок не требуется загружать все сведения о книге.

Достаточно названия и автора.

После ответа результат проверяется:

```javascript
if (!controller.signal.aborted) {
    setSuggestions(result);
}
```

Перед сохранением результата проверяется свойство `controller.signal.aborted`.

Если запрос был отменён, свойство имеет значение `true`, и результат не записывается в состояние подсказок.

Это позволяет не использовать ответ от устаревшего запроса.

### 8.13. Обработка ошибки автоподсказок

```javascript
} catch (error) {
    if (controller.signal.aborted) {
        return;
    }

    setSuggestions([]);
    console.error("Ошибка получения подсказок:", error);
}
```

Если запрос был отменён, проверка `controller.signal.aborted` позволяет завершить обработку без вывода ошибки в консоль.

Если произошла обычная ошибка API или сети:

- список подсказок очищается;
- ошибка выводится в консоль;
- интерфейс не показывает отдельное сообщение об ошибке автоподсказок.

Основной поиск при этом остаётся отдельной функцией и может быть выполнен самостоятельно.

### 8.14. Завершение загрузки подсказок

```javascript
finally {
    if (!controller.signal.aborted) {
        setSuggestionsLoading(false);
    }
}
```

`finally` выполняется после завершения `try` или `catch`.

Перед сбросом состояния загрузки проверяется, не был ли запрос отменён.

Если запрос актуален, вызывается `setSuggestionsLoading(false)`.

Если запрос отменён, обновление состояния из старого эффекта не выполняется. Это позволяет избежать вмешательства предыдущего запроса в состояние нового.

### 8.15. Очистка эффекта

```javascript
return () => {
    controller.abort();
    clearTimeout(timeoutId);
};
```

При очистке эффекта выполняются две операции:

1. `controller.abort()` — отправляет сигнал отмены предыдущего HTTP-запроса.
2. `clearTimeout(timeoutId)` — отменяет ожидающий таймер, если он ещё не успел сработать.

Таким образом, приложение учитывает две ситуации:

- Если запрос ещё не был отправлен, очищается таймер.
- Если HTTP-запрос уже выполняется, он отменяется через `AbortController`.

В отличие от прежнего флага `isCurrentRequest`, новый механизм позволяет не только игнорировать устаревший результат, но и отменять сам клиентский HTTP-запрос.

### 8.16. Функция основного поиска

```javascript
const handleSearch = async (event, searchValue = query) => {
    event?.preventDefault();

    const normalizedQuery = searchValue.trim();

    // ...
};
```

`handleSearch` выполняет основной поиск.

Это асинхронная функция, поскольку она ожидает ответ от API.

Параметры:

- `event` — событие отправки формы. Оно может отсутствовать, если поиск запускается выбором подсказки.
- `searchValue` — необязательное значение запроса. Если оно не передано, используется текущий `query`.

### 8.17. Предотвращение перезагрузки страницы

```javascript
event?.preventDefault();
```

`preventDefault()` отменяет стандартное поведение отправки HTML-формы.

По умолчанию браузер может выполнить переход или перезагрузить страницу.

В React-приложении это не требуется: поиск должен выполняться через JavaScript без полной перезагрузки.

Оператор `?.` позволяет безопасно вызвать метод, если `event` существует.

Если передан `null`, ошибка не возникает.

### 8.18. Проверка пустого запроса

```javascript
if (!normalizedQuery) {
    setBooks([]);
    setError("Введите название книги для поиска.");
    setSearched(false);
    return;
}
```

Если после `trim()` строка пустая, функция:

1. Очищает предыдущие результаты.
2. Записывает сообщение об ошибке.
3. Сбрасывает признак выполненного поиска.
4. Завершает выполнение.

До функции `searchBooks` выполнение не доходит.

Следовательно, пустой запрос не отправляется в API.

### 8.19. Подготовка нового поиска

```javascript
setLoading(true);
setError(null);
setBooks([]);
setSearched(false);
```

Перед отправкой нового запроса:

- включается индикатор загрузки;
- очищается предыдущая ошибка;
- удаляются старые результаты;
- сбрасывается признак успешного поиска.

Затем выполняется запрос.

### 8.20. Успешный поиск

```javascript
try {
    const result = await searchBooks(normalizedQuery);
    setBooks(result);
    setSearched(true);
}
```

`await` ожидает завершения запроса.

После получения данных массив записывается в `books`.

`setSearched(true)` указывает, что поиск завершён успешно, даже если API вернул пустой массив.

### 8.21. Обработка ошибки поиска

```javascript
catch (error) {
    setError(
        error instanceof Error
            ? error.message
            : "Не удалось выполнить поиск. Попробуйте ещё раз."
    );
}
```

Если возникла ошибка:

- проверяется, является ли она экземпляром `Error`;
- если да, пользователю передаётся её сообщение;
- если нет, устанавливается общее сообщение.

### 8.22. Завершение поиска

```javascript
finally {
    setLoading(false);
}
```

После успешного выполнения или ошибки загрузка завершается.

Таким образом, основной поиск не оставляет интерфейс в состоянии бесконечной загрузки при обычном завершении запроса.

### 8.23. Возвращаемые значения хука

```javascript
return {
    query,
    setQuery,
    books,
    loading,
    error,
    searched,
    handleSearch,
    suggestions,
    suggestionsLoading,
};
```

Компонент `App` получает все значения, необходимые для отображения страницы и обработки действий пользователя.

## 9. Автоподсказки при поиске

Автоподсказки реализованы совместно в двух файлах:

```text
src/hooks/useLogic.js
```

### 9.1. Компонент Autocomplete

В `Main.jsx` используется:

```jsx
<Autocomplete
    fullWidth
    freeSolo
    options={suggestions}
    loading={suggestionsLoading}
    disabled={loading}
    inputValue={query}
    onInputChange={handleInputChange}
    // ...
/>
```

Разберём основные свойства.

**`fullWidth`**
Заставляет компонент занимать доступную ширину.

**`freeSolo`**
Разрешает использовать произвольный введённый текст, даже если пользователь не выбрал готовую подсказку.

**`options`**
Передаёт список вариантов для отображения.
В нашем случае это массив `suggestions`.

**`loading`**
Передаёт состояние загрузки подсказок.

**`disabled`**
Блокирует поле во время выполнения основного поиска.

**`inputValue`**
Связывает поле ввода с состоянием `query`.
Это означает, что значение поля контролируется React.

### 9.2. Обработка ввода
```jsx
const handleInputChange = (event, newInputValue, reason) => {
    if (reason === "input" || reason === "clear") {
        setQuery(newInputValue);
    }
};
```

`handleInputChange` — отдельная функция обработки изменения текста, которая передаётся в свойство `onInputChange` компонента `Autocomplete`.

Параметры:

- `event` — событие.
- `newInputValue` — новое значение поля.
- `reason` — причина изменения.

В текущей реализации поисковая строка обновляется только при вводе текста (`input`) или очистке поля (`clear`).

Вынесение обработчика из JSX позволяет отделить логику взаимодействия с пользователем от описания интерфейса.

### 9.3. Выбор подсказки

```jsx
const handleAutocompleteChange = (event, selectedBook) => {
    if (selectedBook && typeof selectedBook !== "string") {
        const selectedTitle = selectedBook.Title || "";

        setQuery(selectedTitle);
        handleSearch(null, selectedTitle);
    }
};
```
Пример подключения:
```jsx
onChange={handleAutocompleteChange}
```

Когда пользователь выбирает книгу:

1. Проверяется, что выбран объект книги.
2. Из него извлекается название.
3. Название записывается в поисковую строку.
4. Выполняется полноценный поиск по выбранному названию.

Передача `null` вместо события возможна благодаря необязательной проверке `event?.preventDefault()` в `handleSearch`.

Обработчик `handleAutocompleteChange` вынесен отдельно от JSX. Он получает выбранную книгу, обновляет поисковую строку и запускает основной поиск.

### 9.4. Настройка фильтрации

```jsx
const filterAutocompleteOptions = (options) => {
    return options;
};
```

```jsx
filterOptions={filterAutocompleteOptions}
```
Функция `filterAutocompleteOptions` вынесена отдельно от JSX. Она возвращает исходный массив вариантов без дополнительной фильтрации со стороны MUI.

MUI обычно может самостоятельно фильтровать варианты, основываясь на введённом тексте.
В данном приложении возвращается исходный массив вариантов.
Это позволяет использовать результаты фильтрации, которые уже получены от внешнего API.

### 9.5. Отображение названия книги

```jsx
const getAutocompleteOptionLabel = (option) => {
    if (typeof option === "string") {
        return option;
    }

    return option.Title || "";

```

```jsx
getOptionLabel={getAutocompleteOptionLabel}
```

Функция `getAutocompleteOptionLabel` описана отдельно и передаётся компоненту через свойство `getOptionLabel`.

Функция определяет, какой текст отображать в поле.
Если передана строка, возвращается сама строка.
Если передан объект книги, возвращается его `Title`.

### 9.6. Отображение варианта подсказки

```jsx
const renderAutocompleteOption = (props, option) => {
```

Параметры:

Свойства MUI передаются элементу `<li>` через `{...props}`. Это необходимо для корректной работы выбора подсказок и взаимодействия со списком.

## 10. Работа с API

Основная работа с внешним API находится в:

```text
src/api/constants.js
src/api/searchBooks.js
```

Используется сервис:

**Book Metadata Service**

Официальный сайт:
https://bookmetadata.ru/

Документация API:
https://bookmetadata.ru/docs

### 10.1. Назначение API

API предоставляет информацию о книжных изданиях.

В проекте оно используется для:

- Поиска книг по названию.
- Поиска по ISBN.
- Получения вариантов для автоподсказок.

API не требует передачи собственного ключа или регистрации для используемых публичных методов.

Ограничение сервиса — 60 запросов в минуту с одного IP-адреса. Также документация указывает допустимый кратковременный всплеск запросов.

### 10.2. Константы API

Файл:

```text
src/api/constants.js
```

Содержимое:

```javascript
export const API_URL = "https://bookmetadata.ru/api/v1/search";
export const REQUEST_TIMEOUT_MS = 10000;
```

`API_URL` — адрес используемого маршрута API.

`REQUEST_TIMEOUT_MS` — максимальное время ожидания ответа.

Значение:

```javascript
10000
```
означает 10 000 миллисекунд, то есть 10 секунд.
Использование отдельных констант позволяет не дублировать адрес и время ожидания в разных частях программы.

### 10.3. Универсальный маршрут

Приложение использует:

```text
https://bookmetadata.ru/api/v1/search
```

Для обычного поиска используется параметр:

```text
q
```

Примеры:

```text
/api/v1/search?q=Гарри%20Поттер
```

```text
/api/v1/search?q=9785389143852
```

В обоих случаях используется один универсальный маршрут.

Сам сервис определяет, похож ли запрос на ISBN, и выбирает соответствующий способ обработки.

В приложении не реализованы отдельные HTTP-вызовы к маршрутам `/search/isbn/...` или `/search/title`.

### 10.4. Дополнительный параметр fields

Для автоподсказок используется дополнительный параметр:

```text
fields=Title,AuthorName
```

Он ограничивает набор запрашиваемых полей.

Например:

```text
/api/v1/search?q=Гарри%20Поттер&fields=Title,AuthorName
```

Это позволяет получать только название и автора, необходимые для списка подсказок.

Обычный поиск вызывается без параметра `fields` и получает полный набор доступных публичных полей API.

### 10.5. Функция prepareQuery

В `searchBooks.js` находится вспомогательная функция:

```javascript
function prepareQuery(query) {
    const normalizedISBN = query.replace(/[\s-]/g, "");
    const isISBN = /^\d{9}[\dXx]$|^\d{13}$/.test(normalizedISBN);

    return isISBN ? normalizedISBN.toUpperCase() : query;
}
```

Её назначение — подготовить запрос, если он похож на ISBN.

Первая строка:

```javascript
const normalizedISBN = query.replace(/[\s-]/g, "");
```

Удаляет пробелы и дефисы.

Например:

```text
978-5-389-14385-2
```

превращается в:

```text
9785389143852
```

Затем выполняется регулярное выражение:

```javascript
/^\d{9}[\dXx]$|^\d{13}$/
```

Оно проверяет форму строки:

- ISBN-10 — девять цифр и последняя цифра либо X.
- ISBN-13 — тринадцать цифр.

Буква X может быть как заглавной, так и строчной.

Если строка соответствует одному из шаблонов, используется нормализованный вариант:

```javascript
normalizedISBN.toUpperCase()
```

Это приводит символ `x` к заглавной букве `X`.

**Важно:** эта функция проверяет форму записи, но не вычисляет контрольную сумму ISBN. Проверка ISBN при универсальном поиске выполняется самим API.

Если запрос не похож на ISBN, функция возвращает исходную строку.

### 10.6. Основная функция searchBooks

```javascript
export async function searchBooks(query, fields, signal) {
    let response;

    const params = {
        q: prepareQuery(query),
    };

    if (fields) {
        params.fields = fields;
    }

    // ...
}
```

Функция принимает:

- `query` — текст поискового запроса.
- `fields` — необязательный список запрашиваемых полей.
- `signal` — необязательный сигнал отмены HTTP-запроса.

Параметр `signal` используется при получении автоподсказок.

Для обычного поиска он не передаётся, поскольку основной поиск вызывается без третьего аргумента:
```jsx
searchBooks(normalizedQuery);
```

Для автоподсказок передаётся сигнал, созданный через AbortController:
```jsx
searchBooks(
    normalizedQuery,
    "Title,AuthorName",
    controller.signal
);
```

Сначала создаётся объект `params`.
В нём находится параметр `q` с подготовленным поисковым запросом.
Если передан `fields`, он также добавляется в параметры.

### 10.7. Выполнение Axios-запроса

```jsx
response = await axios.get(API_URL, {
    params,
    timeout: REQUEST_TIMEOUT_MS,
    signal,
});
```

`axios.get()` выполняет GET-запрос.
`API_URL` определяет маршрут сервера.
`params` содержит параметры строки запроса.
`timeout` задаёт максимальное время ожидания ответа.
`signal` — сигнал отмены запроса.

Если он передан, Axios связывает запрос с соответствующим `AbortController`. При вызове `controller.abort()` запрос отменяется.

Если `signal` не передан, как при обычном поиске, Axios выполняет запрос без дополнительного механизма отмены.

Поскольку используется `await`, функция ждёт завершения запроса.

### 10.8. Проверка ошибки Axios

```javascript
if (axios.isCancel(error)) {
    throw error;
}

if (!axios.isAxiosError(error)) {
    throw error;
}
```

Проверяется, действительно ли полученная ошибка относится к Axios.

Если это другая ошибка, она передаётся выше без преобразования.

Это позволяет не приписывать сетевым ошибкам все возможные проблемы JavaScript.

Перед стандартной проверкой Axios выполняется `axios.isCancel(error)`.

Она позволяет определить, что запрос был отменён.

Если обнаружена отмена, исходная ошибка передаётся выше через `throw error`, а не преобразуется в обычное сообщение о сетевой или HTTP-ошибке.

В `useLogic.js` такая ситуация дополнительно проверяется через `controller.signal.aborted`. Поэтому отменённый запрос не обрабатывается как обычная ошибка автоподсказок.

### 10.9. Обработка HTTP 429

```javascript
if (error.response.status === 429) {
    throw new Error(
        "Слишком много запросов. Попробуйте немного позже.",
        {
            cause: error,
        }
    );
}
```

HTTP 429 означает, что превышен лимит запросов.
Приложение создаёт отдельное сообщение для пользователя.

### 10.10. Обработка других HTTP-ошибок

```javascript
throw new Error(
    `Ошибка сервера: HTTP ${error.response.status}`,
    {
        cause: error,
    }
);
```

Для других HTTP-ошибок формируется сообщение с кодом ответа.
Например:
```text
Ошибка сервера: HTTP 500
```
Исходная ошибка Axios сохраняется в `cause`.

### 10.11. Обработка тайм-аута

```javascript
if (
    error.code === "ECONNABORTED" ||
    error.code === "ETIMEDOUT"
) {
    throw new Error(
        "Сервер не ответил за 10 секунд. Попробуйте ещё раз.",
        {
            cause: error,
        }
    );
}
```

Если Axios сообщает об истечении времени ожидания, приложение выводит отдельное сообщение.
Это связано с настройкой `REQUEST_TIMEOUT_MS`.

### 10.12. Отсутствие ответа от сервера

```javascript
if (error.request) {
    throw new Error(
        "Не удалось получить ответ от API. Проверьте интернет",
        {
            cause: error,
        }
    );
}
```
Если запрос был создан, но ответ от сервера не получен, отображается сообщение о проблеме соединения.

### 10.13. Другие ошибки запроса

Если возникла другая ошибка Axios, используется общее сообщение:

```javascript
throw new Error("Не удалось выполнить запрос к API.", {
    cause: error,
});
```

### 10.14. Проверка ответа API

После успешного запроса выполняется:

```javascript
if (!Array.isArray(response.data)) {
    throw new Error(
        "Сервер вернул данные в неизвестном формате"
    );
}
```

Приложение ожидает массив.
Если сервер вернул другой тип данных, создаётся ошибка.
Если проверка пройдена, возвращается:

```javascript
return response.data;
```

Таким образом, остальные части приложения получают готовый массив книг.
**Важно:** текущая функция проверяет именно то, что ответ является массивом. Она не выполняет полную проверку типов всех полей каждого объекта. Отсутствующие поля дополнительно обрабатываются в компоненте карточки.

## 11. Подробный разбор `useFavorite.js`

Этот пользовательский хук отвечает за работу с избранными книгами.

Его основные задачи:

1. Получить ранее сохранённые книги.
2. Хранить список избранного в React state.
3. Добавлять книги.
4. Не допускать дубликатов.
5. Удалять книги.
6. Проверять, находится ли книга в избранном.
7. Записывать изменения в `localStorage`.

### 11.1. Ключ localStorage

```javascript
const STORAGE_KEY = "favoriteBooks";
```

Это имя ключа, под которым данные будут храниться в браузере.
Через этот ключ приложение получает и записывает список избранных книг.

### 11.2. Функция getStoredFavorites

```javascript
function getStoredFavorites() {
    try {
        const savedFavorites = localStorage.getItem(STORAGE_KEY);

        if (!savedFavorites) {
            return [];
        }

        const parsedFavorites = JSON.parse(savedFavorites);

        return Array.isArray(parsedFavorites)
            ? parsedFavorites
            : [];
    } catch (error) {
        console.error("Ошибка чтения избранного:", error);
        return [];
    }
}
```

Функция отвечает за первоначальное чтение избранного из браузера.
Сначала вызывается:

```javascript
localStorage.getItem(STORAGE_KEY)
```
Метод получает строку, сохранённую под ключом `favoriteBooks`.
Если записи нет, возвращается пустой массив.
Если запись существует, выполняется:

```javascript
JSON.parse(savedFavorites)
```

`JSON.parse` преобразует JSON-строку в JavaScript-значение.
Затем проверяется:

```javascript
Array.isArray(parsedFavorites)
```

Приложение ожидает именно массив.
Если данные отсутствуют, имеют неправильный формат или чтение завершилось ошибкой, функция возвращает пустой массив.

### 11.3. Зачем нужен try/catch

Операции с хранилищем и разбор JSON могут завершиться ошибкой.
Например:
- В хранилище записана повреждённая JSON-строка.
- Браузер не разрешает доступ к хранилищу.
- Возникла ошибка чтения данных.

`try/catch` позволяет обработать такие ситуации, не останавливая работу всего приложения.

### 11.4. Функция getBookId

```javascript
function getBookId(book) {
    if (!book || typeof book !== "object") {
        return null;
    }

    // ...
}
```

Функция определяет идентификатор книги.
Она нужна для того, чтобы понимать, является ли две записи одной и той же книгой.
В API могут встречаться записи с разным набором полей, поэтому используется несколько вариантов идентификации.

### 11.5. Первый способ — guid

```javascript
if (book.guid) {
    return `guid:${book.guid}`;
}
```

Если у книги есть `guid`, он используется в качестве основного идентификатора.
Это предпочтительный вариант, поскольку `guid` предназначен для уникальной идентификации записи.

### 11.6. Второй способ — ISBN

```javascript
if (book.ISBN) {
    const normalizedISBN = String(book.ISBN)
        .replace(/[\s-]/g, "")
        .toUpperCase();

    return `isbn:${normalizedISBN}`;
}
```

Если `guid` отсутствует, используется ISBN.
Перед сравнением удаляются пробелы и дефисы.
Буквы переводятся в верхний регистр.
Это позволяет считать одинаковыми варианты ISBN, записанные с разными разделителями.
Например:

```text
978-5-389-14385-2
```
и:
```text
9785389143852
```

будут иметь одинаковый нормализованный идентификатор.

### 11.7. Третий способ — название и автор

```javascript
if (typeof book.Title === "string" && book.Title.trim()) {
    const title = book.Title.trim().toLowerCase();

    const author =
        typeof book.AuthorName === "string"
            ? book.AuthorName.trim().toLowerCase()
            : "";

    return `title:${title}|author:${author}`;
}
```

Если в записи нет `guid` и ISBN, используются название и автор.
Оба поля очищаются от крайних пробелов и переводятся в нижний регистр.
Так приложение может определить повтор одной и той же записи даже при отсутствии уникального идентификатора.
Если ни один вариант не подходит, возвращается `null`.

### 11.8. Создание состояния избранного

```javascript
const [favorites, setFavorites] = useState(getStoredFavorites);
```

Состояние `favorites` хранит массив избранных книг.
В качестве начального значения передаётся функция `getStoredFavorites`.
React вызывает её при первоначальной инициализации состояния, чтобы получить данные из `localStorage`.

### 11.9. Автоматическое сохранение данных

```javascript
useEffect(() => {
    try {
        localStorage.setItem(
            STORAGE_KEY,
            JSON.stringify(favorites)
        );
    } catch (error) {
        console.error("Ошибка сохранения избранного:", error);
    }
}, [favorites]);
```

Этот эффект запускается при изменении `favorites`.

Сначала:

```javascript
JSON.stringify(favorites)
```
Преобразует массив объектов в JSON-строку.

Затем:

```javascript
localStorage.setItem(...)
```
Записывает строку в браузер под ключом `favoriteBooks`.
Таким образом, приложение не требует вручную сохранять данные после каждого действия.
Когда состояние меняется, `useEffect` выполняет запись автоматически.
Если запись не удалась, ошибка выводится в консоль.

### 11.10. Добавление книги

```javascript
const addFavorite = (book) => {
    const bookId = getBookId(book);

    if (!bookId) {
        return;
    }

    // ...
};
```

Сначала вычисляется идентификатор книги.
Если определить его невозможно, добавление не выполняется.
Затем используется обновление состояния на основе предыдущего значения:

```javascript
setFavorites((currentFavorites) => {
    // ...
});
```

Это функциональная форма `setState`.
Она позволяет получить актуальный список избранного, даже если несколько обновлений выполняются близко друг к другу.

### 11.11. Проверка дубликата

```javascript
const alreadyExists = currentFavorites.some(
    (favorite) => getBookId(favorite) === bookId
);
```

Метод `some()` проверяет, существует ли хотя бы один элемент, удовлетворяющий условию.
Здесь сравниваются идентификаторы сохранённых книг и добавляемой книги.
Если книга уже существует, функция возвращает прежний массив.

```javascript
if (alreadyExists) {
    return currentFavorites;
}
```

Если дубликата нет, формируется новый массив:

```javascript
return [...currentFavorites, book];
```

Оператор `...` копирует существующие элементы массива, после чего добавляется новая книга.

### 11.12. Удаление книги

```javascript
const removeFavorite = (book) => {
    const bookId = getBookId(book);

    if (!bookId) {
        return;
    }

    setFavorites((currentFavorites) =>
        currentFavorites.filter(
            (favorite) => getBookId(favorite) !== bookId
        )
    );
};
```

Для удаления также сначала определяется идентификатор.
Затем используется `filter()`.
В новый массив попадают только книги, идентификаторы которых не совпадают с удаляемой книгой.
В результате выбранная запись удаляется из состояния.
После изменения состояния `useEffect` автоматически сохраняет новый список в `localStorage`.

### 11.13. Проверка избранного

```javascript
const isFavorite = (book) => {
    const bookId = getBookId(book);

    if (!bookId) {
        return false;
    }

    return favorites.some(
        (favorite) => getBookId(favorite) === bookId
    );
};
```
Функция проверяет, находится ли конкретная книга в списке избранного.
Если идентификатор получить невозможно, возвращается `false`.
В противном случае выполняется поиск по массиву через `some()`.

### 11.14. Возвращаемые значения

```javascript
return {
    favorites,
    addFavorite,
    removeFavorite,
    isFavorite,
};
```

Хук предоставляет компонентам:
|     Значение     |            Назначение              |
| `favorites`      | Список избранных книг              |
| `addFavorite`    | Добавление книги                   |
| `removeFavorite` | Удаление книги                     |
| `isFavorite`     | Проверка наличия книги в избранном |

**Особенность текущей архитектуры:** хук используется отдельно в `Main` и `Favorites`. Он не передаёт состояние между страницами через Context или Redux. Обмен между отдельными экземплярами хука происходит через `localStorage`.

## 12. Страница избранного

Файл:

```text
src/pages/Favorites.jsx
```
Компонент `Favorites` отвечает за отображение сохранённых книг.

### 12.1. Локальное состояние фильтра

```javascript
const [searchQuery, setSearchQuery] = useState("");
```

`searchQuery` хранит текст, который пользователь вводит в поле поиска избранного.
Это отдельное состояние, не связанное с основной строкой поиска на главной странице.

### 12.2. Использование useFavorite

```javascript
const {
    favorites,
    removeFavorite,
    isFavorite,
} = useFavorite();
```
Страница получает список избранного и функции для работы с ним.

### 12.3. Нормализация строки фильтра

```javascript
const normalizedQuery = searchQuery.trim().toLowerCase();
```

Перед сравнением:
- удаляются крайние пробелы;
- текст переводится в нижний регистр.
Это делает поиск нечувствительным к регистру.

### 12.4. Фильтрация книг

```javascript
const filteredFavorites = favorites.filter((book) => {
    const searchableText = [
        book.Title || "",
        book.AuthorName || "",
        book.ISBN || "",
    ]
        .join(" ")
        .toLowerCase();

    return searchableText.includes(normalizedQuery);
});
```

Для каждой книги формируется строка из:
- названия;
- автора;
- ISBN.

Метод `join(" ")` соединяет эти значения через пробел.
Затем строка переводится в нижний регистр.
`includes()` проверяет, содержится ли поисковое значение внутри сформированной строки.
Если совпадение есть, книга попадает в `filteredFavorites`.
Таким образом, можно найти сохранённую книгу по названию, автору или ISBN.

### 12.5. Отображение пустого списка

```jsx
{favorites.length === 0 && (
    <Alert severity="info">
        В избранном пока нет книг.
    </Alert>
)}
```
Если список избранного пустой, выводится информационное сообщение.

### 12.6. Отображение отсутствия совпадений

```jsx
{favorites.length > 0 && filteredFavorites.length === 0 && (
    <Alert severity="info">
        По вашему запросу ничего не найдено.
    </Alert>
)}
```

Это отдельная ситуация.
В избранном есть книги, но по текущей строке фильтра ничего не найдено.

### 12.7. Отображение отфильтрованных карточек

```jsx
{filteredFavorites.length > 0 && (
    <Box className="books-grid">
        {filteredFavorites.map((book, index) => (
            <BookCard
                key={book.guid || book.ISBN || index}
                book={book}
                isFavorite={isFavorite(book)}
                onToggleFavorite={removeFavorite}
            />
        ))}
    </Box>
)}
```

Здесь используется тот же компонент `BookCard`, который применяется на главной странице.
Однако функция `onToggleFavorite` получает `removeFavorite`.
Это означает, что на странице избранного нажатие кнопки сердца удаляет книгу из списка.

### 12.8. Возврат к поиску

```jsx
<Button
    component={Link}
    to="/"
    variant="contained"
>
    Вернуться к поиску
</Button>
```

Кнопка использует компонент `Link` из React Router.
При нажатии пользователь возвращается на маршрут `/`.

### 12.9. Обработка изменения поискового поля

Для обработки изменения текста в поле поиска используется отдельная функция:

```jsx
const handleSearchQueryChange = (event) => {
    setSearchQuery(event.target.value);
};
```

event.target.value содержит текущее значение поискового поля.

Полученный текст сохраняется в состояние searchQuery с помощью setSearchQuery.

Функция передаётся компоненту TextField через свойство onChange:
```jsx
<TextField
    fullWidth
    label="Поиск в избранном"
    placeholder="Введите название книги, автора или ISBN"
    value={searchQuery}
    onChange={handleSearchQueryChange}
/>
```

Обработчик вынесен за пределы JSX. Это позволяет отделить логику изменения поисковой строки от описания самого поля ввода.

## 13. Подробный разбор `BookCard`

Файл:

```text
src/bookCard.jsx
```

`BookCard` — компонент, который отображает одну книгу.
Он используется и в результатах поиска, и на странице избранного.
Благодаря этому не требуется создавать два отдельных компонента с одинаковой разметкой.

### 13.1. Получение props

```javascript
function BookCard({
    book,
    isFavorite = false,
    onToggleFavorite
}) {
```

Компонент получает три свойства.

|        Prop        |          Назначение             |
| `book`             | Объект с данными книги          |
| `isFavorite`       | Находится ли книга в избранном  |
| `onToggleFavorite` | Функция добавления или удаления |

`isFavorite` имеет значение `false` по умолчанию.

### 13.2. Локальное состояние карточки

```javascript
const [expanded, setExpanded] = useState(false);
const [failedCoverUrl, setFailedCoverUrl] = useState("");
```

Первое состояние:
`expanded` определяет, раскрыто ли описание книги.

Второе состояние:
`failedCoverUrl` хранит адрес обложки, загрузка которой завершилась ошибкой.

Эти состояния относятся только к конкретной карточке.

### 13.3. Получение названия

```javascript
const title =
    typeof book.Title === "string" && book.Title.trim()
        ? book.Title
        : "Эх, названия нет";
```

Сначала проверяется, является ли название строкой и содержит ли оно непустой текст.
Если значение отсутствует или некорректно, используется заглушка.
Так карточка может отображаться даже при неполных данных API.

### 13.4. Получение автора

```javascript
const author =
    typeof book.AuthorName === "string" && book.AuthorName.trim()
        ? book.AuthorName
        : "Эх, автор неизвестен";
```
Аналогичная проверка применяется к имени автора.

### 13.5. Получение года издания

```javascript
const publishedYear =
    (typeof book.PublishedYear === "string" &&
        book.PublishedYear.trim()) ||
    (typeof book.PublishedYear === "number" &&
        Number.isFinite(book.PublishedYear))
        ? book.PublishedYear
        : "Эх, год издания неизвестен";
```

Год может прийти в виде строки или конечного числового значения.
`Number.isFinite()` проверяет, что число является конечным и не равно `NaN` или бесконечности.
Если подходящего значения нет, отображается заглушка.

### 13.6. Получение ISBN и издательства

Для ISBN:

```javascript
const isbn =
    typeof book.ISBN === "string" && book.ISBN.trim()
        ? book.ISBN
        : "Эх, ISBN не указан";
```

Для издательства:

```javascript
const publisher =
    typeof book.Publisher === "string" && book.Publisher.trim()
        ? book.Publisher
        : "Эх, издательство не указано";
```

Обе проверки позволяют обработать отсутствующие поля.

### 13.7. Получение описания

```javascript
const description =
    typeof book.Description === "string" && book.Description.trim()
        ? book.Description
        : "Эх, описание отсутствует";
```

Если описание есть, используется значение API.
Если его нет, отображается заглушка.

### 13.8. Получение обложки

```javascript
const coverUrl =
    typeof book.CoverUrl === "string" && book.CoverUrl.trim()
        ? book.CoverUrl
        : "";
```

Здесь проверяется, что адрес обложки является непустой строкой.
Если URL отсутствует, используется placeholder.

### 13.9. Отображение изображения

```jsx
{coverUrl && failedCoverUrl !== coverUrl ? (
    <CardMedia
        component="img"
        image={coverUrl}
        alt={title}
        className="book-cover"
        onError={handleCoverError}
    />
) : (
    <Box className="book-cover-placeholder">
        <Typography variant="body2">
            Ну тут тип обложка должна быть, но автор не добавил
        </Typography>
    </Box>
)}
```

Если адрес обложки существует и загрузка ранее не завершалась ошибкой, отображается `CardMedia`.

```jsx
const handleCoverError = () => {
    setFailedCoverUrl(coverUrl);
};
```
Обработчик `handleCoverError` описан отдельно внутри компонента `BookCard`.

Он вызывается при ошибке загрузки изображения и записывает проблемный адрес в состояние `failedCoverUrl`.

После этого компонент вместо изображения отображает placeholder.

Вынос функции из JSX позволяет не размещать логику обработки ошибки непосредственно в разметке.

Если URL отсутствует или загрузка изображения не удалась, отображается placeholder.

Событие `onError` вызывается браузером, когда изображение не удалось загрузить.

После этого адрес сохраняется в `failedCoverUrl`, и вместо изображения отображается заглушка.


### 13.10. Отображение основных данных

Внутри `CardContent` выводятся:
- Название.
- Автор.
- Год издания.
- ISBN.
- Издательство.
- Описание.

Данные берутся из подготовленных значений `title`, `author`, `publishedYear`, `isbn`, `publisher` и `description`.

### 13.11. Кнопка избранного

```jsx
const handleToggleFavorite = () => {
    onToggleFavorite?.(book);
};

<IconButton
    type="button"
    color={isFavorite ? "error" : "default"}
    aria-label={
        isFavorite
            ? "Удалить из избранного"
            : "Добавить в избранное"
    }
    aria-pressed={isFavorite}
    onClick={handleToggleFavorite}
>
    <span aria-hidden="true">
        {isFavorite ? "♥" : "♡"}
    </span>
</IconButton>
```

Кнопка меняет цвет и символ в зависимости от состояния избранного.

`onClick` вызывает переданную функцию.

Оператор `?.` означает, что вызов безопасен, даже если функция не передана.

На главной странице передаётся функция переключения избранного.

На странице избранного передаётся функция удаления.
Функция `handleToggleFavorite` вызывает обработчик `onToggleFavorite`, переданный компоненту через props.

В качестве аргумента передаётся текущая книга `book`.

На главной странице родительский компонент передаёт функцию переключения избранного: книга добавляется или удаляется в зависимости от её текущего состояния.

На странице избранного передаётся функция `removeFavorite`, поэтому нажатие на сердце удаляет книгу из сохранённого списка.

Таким образом, сам `BookCard` не определяет, какую именно операцию необходимо выполнить. Он вызывает функцию, полученную от родительского компонента.

### 13.12. Обрезка описания

```jsx
{expanded
    ? description
    : description.length > 150
        ? description.slice(0, 150) + "..."
        : description}
```

Если описание раскрыто, выводится полный текст.
Если описание не раскрыто и его длина больше 150 символов, показываются первые 150 символов и многоточие.
Если описание короче, отображается полностью.

### 13.13. Кнопка раскрытия

```jsx
const handleToggleExpanded = () => {
    setExpanded(!expanded);
};

{description.length > 150 && (
    <Button
        onClick={handleToggleExpanded}
        size="small"
        aria-expanded={expanded}
    >
        {expanded ? "Сверни меня" : "Разверни меня"}
    </Button>
)}
```
Обработчик `handleToggleExpanded` вынесен отдельно от JSX.

При нажатии он изменяет состояние `expanded` на противоположное:

- Если значение `false`, описание раскрывается.
- Если значение `true`, описание сворачивается.

Свойство `aria-expanded` также получает текущее значение `expanded`, чтобы состояние раскрытия было доступно вспомогательным технологиям.

Кнопка появляется только при длине описания больше 150 символов.
При нажатии значение `expanded` меняется на противоположное.
Это позволяет переключаться между кратким и полным описанием.

## 14. Состояния приложения и обработка ошибок

В проекте используются отдельные состояния для основного поиска и автоподсказок.

### 14.1. Основные состояния поиска

|       Состояние          |               Условие                   |          Отображение        |
| Начальное                | Поиск ещё не выполнялся                 |Пустая область результатов   |
| Загрузка                 | `loading === true`                      | Индикатор загрузки          |
| Ошибка                   | `error !== null` и загрузка завершена   | Сообщение об ошибке         |
| Успешный поиск без резов | `searched === true`и`books.length === 0`| Сообщение об отсутствии книг|
| Успешный поиск с резами  | `books.length > 0`                      | Список карточек             |

### 14.2. Начальное состояние

После открытия страницы:

```javascript
loading = false
error = null
searched = false
books = []
```
Поэтому приложение не показывает пользователю сообщение об отсутствии результатов до первого поиска.

### 14.3. Состояние загрузки

Во время основного поиска:

```javascript
setLoading(true);
```

В интерфейсе отображаются:
- `CircularProgress`;
- сообщение о загрузке.

Поле поиска и кнопка становятся недоступными.

### 14.4. Состояние ошибки

Если запрос завершился ошибкой, `useLogic` сохраняет текст сообщения в `error`.
Главная страница проверяет:

```jsx
{!loading && error && (
    <Alert severity="error">
        {error}
    </Alert>
)}
```
Ошибка отображается после завершения загрузки.

### 14.5. Пустой результат

Если API вернул пустой массив, ошибки нет, но и книг нет.
Проверка:

```jsx
!loading && searched && books.length === 0
```
В этом случае отображается отдельное информационное сообщение.

### 14.6. Успешный результат

Если массив содержит книги:

```jsx
!loading && books.length > 0
```
Показывается заголовок с количеством найденных книг и сами карточки.

### 14.7. Сводная таблица обработки ошибок

|             Ситуация             |                            Обработка                                |
| Пустой запрос                    | Ошибка в состоянии, без обращения к API                             |
| HTTP 429                         | Отдельное сообщение о превышении лимита                             |
| Другой HTTP-статус ошибки        | Сообщение с HTTP-кодом                                              |
| Тайм-аут                         | Сообщение о превышении 10 секунд                                    |
| Запрос без ответа                | Сообщение о проблеме соединения                                     |
| Другая ошибка Axios              | Общее сообщение об ошибке API                                       |
| Ответ не является массивом       | Ошибка неизвестного формата                                         |
| Ошибка автоподсказок             | Подсказки очищаются, ошибка записывается в консоль                  |
| Отмена автоподсказок             | Запрос отменяется через `AbortController`, отмена не показывается   |
|                                  | как обычная ошибка                                                  |
| Отсутствующая обложка            | Отображается placeholder                                            |
| Неполные данные книги            | Для отсутствующих полей используются заглушки                       |
| Некорректный формат localStorage | Чтение обрабатывается через `try/catch`, возвращается пустой массив |

## 15. Стилизация и Material UI

В проекте используются два основных CSS-файла:

```text
src/index.css
src/App.css
```

### 15.1. Глобальные стили — index.css

В этом файле находятся базовые правила, применяемые ко всему документу.

Например:

```css
* {
    box-sizing: border-box;
}
```

`box-sizing: border-box` включает границы и внутренние отступы в общую ширину и высоту элементов.
Это упрощает управление размерами блоков.
Также задаются базовые стили `html`, `body` и шрифта.

### 15.2. Основные стили — App.css

Файл отвечает за расположение и оформление элементов приложения.

1. **Контейнер:**
```css
.app-container {
    padding-top: 40px;
    padding-bottom: 40px;
}
```
Задаёт верхний и нижний отступ страницы.

2. **Заголовок:**
```css
.app-header {
    margin-bottom: 30px;
    text-align: center;
}
```
Центрирует заголовок и добавляет отступ снизу.

3. **Форма поиска:**
```css
.search-form {
    display: flex;
    gap: 12px;
    align-items: flex-start;
    max-width: 800px;
    margin: 0 auto 30px;
}
```
Используется Flexbox.
Поле и кнопка располагаются в одной строке.

`gap` задаёт расстояние между ними.
`max-width` ограничивает ширину формы.
`margin: 0 auto` центрирует блок.

### 15.3. Сетка карточек

```css
.books-grid {
    display: grid;
    grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
    gap: 20px;
    margin-top: 25px;
    align-items: start;
}
```

Для расположения карточек используется CSS Grid.
`repeat(auto-fill, ...)` позволяет автоматически формировать необходимое количество колонок.
`minmax(280px, 1fr)` задаёт минимальную ширину карточки 280 пикселей и позволяет ей занимать свободное пространство.
`gap: 20px` задаёт промежутки между карточками.

### 15.4. Обложка

```css
.book-cover {
    height: 260px;
    object-fit: contain;
    background: #f0f0f0;
}
```

Все обложки имеют одинаковую высоту.
`object-fit: contain` сохраняет пропорции изображения, не обрезая его.
Если изображения нет, аналогичная область используется для placeholder.

### 15.5. Адаптивная вёрстка

```css
@media (max-width: 600px) {
    /* ... */
}
```

Медиа-запрос применяется при ширине экрана до 600 пикселей.

Для мобильных экранов:
- Карточки выстраиваются в одну колонку.
- Форма поиска становится вертикальной.
- Кнопка занимает всю доступную ширину.
- Уменьшается верхний отступ.
- Уменьшается размер заголовка.
Это позволяет использовать приложение на устройствах с небольшой шириной экрана.

### 15.6. Использование MUI вместе с CSS

Material UI отвечает за готовые элементы интерфейса.
CSS задаёт дополнительные правила расположения.
Например, `Container`, `Box` и `Typography` используются для структуры, а `.books-grid` определяет сетку карточек.
Такое разделение позволяет не создавать вручную каждый базовый элемент интерфейса.

## 16. Автоматизированные тесты

Для тестирования проекта используются:
- Vitest;
- React Testing Library;
- jsdom.

Тесты находятся рядом с пользовательскими хуками:

```text
src/hooks/useLogic.test.js
src/hooks/useFavorite.test.js
```

### 16.1. Конфигурация Vitest

Файл:

```text
vite.config.js
```

Содержит:

```javascript
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vitest/config'

export default defineConfig({
    plugins: [react()],
    test: {
        globals: false,
        environment: 'jsdom',
        clearMocks: true,
    },
})
```

`defineConfig` создаёт конфигурацию Vite и Vitest.

`plugins: [react()]` подключает React-плагин.

В секции `test` задаются параметры тестирования:

- `globals: false` — тестовые функции не подключаются как глобальные переменные автоматически, поэтому они импортируются из Vitest.
- `environment: 'jsdom'` — тесты работают в браузероподобном окружении.
- `clearMocks: true` — очищаются данные о вызовах моков.

### 16.2. Что такое renderHook

В тестах используется:

```javascript
import { act, renderHook } from "@testing-library/react";
```

`renderHook` позволяет запустить пользовательский хук и получить доступ к его результату.

Например:

```javascript
const { result } = renderHook(() => useFavorite());
```

`result.current` содержит актуальные значения, возвращаемые хуком.
`act` используется для оборачивания действий, изменяющих состояние React.

Это позволяет корректно проверить результат обновления состояния.

### 16.3. Тестирование useFavorite

Файл:

```text
src/hooks/useFavorite.test.js
```

В этом файле тестируются основные операции избранного.

| № |       Проверяемое поведение          |                Ожидаемый результат                       |
| 1 | Избранное отсутствует в localStorage | Хук возвращает пустой массив                             |
| 2 | Добавление книги                     | Книга появляется в массиве и записывается в localStorage |
| 3 | Повторное добавление той же книги    | Дубликат не создаётся                                    |
| 4 | Удаление книги                       | Книга удаляется из массива и localStorage                |
| 5 | Проверка `isFavorite`                | Функция правильно определяет наличие книги               |
| 6 | Восстановление избранного            | Хук получает ранее сохранённый массив                    |

#### Пример теста добавления книги

```javascript
it("добавляет книгу в избранное", () => {
    const { result } = renderHook(() => useFavorite());

    act(() => {
        result.current.addFavorite(firstBook);
    });

    expect(result.current.favorites).toEqual([firstBook]);
    expect(result.current.isFavorite(firstBook)).toBe(true);
});
```

Сначала запускается хук.
Затем через `act` вызывается `addFavorite`.
После этого проверяется:
- книга появилась в массиве;
- `isFavorite` возвращает `true`.

### 16.4. Тестирование useLogic

Файл:

```text
src/hooks/useLogic.test.js
```

Здесь проверяется логика основного поиска.

Для изоляции тестов API-функция заменяется мок-функцией:

```javascript
vi.mock("../api/searchBooks.js", () => ({
    searchBooks: vi.fn(),
}));
```

Мок позволяет управлять результатом вызова и не обращаться к реальному внешнему серверу.

В текущей реализации тестируются два сценария:
| № |   Проверяемое поведение  |                 Ожидаемый результат                          |
| 1 | Отправка пустого запроса | API не вызывается, появляется сообщение об ошибке            |
| 2 | Успешный поиск           | Полученные книги сохраняются в `books`, загрузка завершается |

#### Проверка пустого поиска

```javascript
expect(searchBooks).not.toHaveBeenCalled();
expect(result.current.books).toEqual([]);
expect(result.current.error).toBe("Введите название книги для поиска.");
expect(result.current.searched).toBe(false);
```

Проверяется, что при пустой строке API не вызывается, список результатов очищен, а сообщение об ошибке установлено.

#### Проверка успешного поиска

```javascript
expect(searchBooks).toHaveBeenCalledWith("Гарри Поттер");
expect(result.current.books).toEqual(books);
expect(result.current.loading).toBe(false);
expect(result.current.error).toBe(null);
expect(result.current.searched).toBe(true);
```

Проверяется, что API-функция была вызвана с правильным запросом, книги сохранены, загрузка завершена и ошибок нет.

### 16.5. Границы текущего покрытия тестами

Существующие тесты проверяют основные сценарии пользовательских хуков.

При этом в текущем наборе отдельно не проверяются:
- HTTP-ошибки и тайм-ауты внутри `searchBooks`.
- Работа автоподсказок и задержки 500 миллисекунд.
- Выбор подсказки на главной странице.
- Отображение карточек `BookCard`.
- Раскрытие и сворачивание описания.
- Работа страницы `Favorites` как React-компонента.
- Интеграция React Router с пользовательским интерфейсом.
- Ошибка чтения и записи `localStorage`.

Наличие тестов не означает, что все возможные сценарии приложения уже проверены.
Актуальные результаты запуска тестов, линтера и сборки следует получать непосредственно в локальной среде.

### 16.6. Команда запуска тестов

```powershell

```

В `package.json` эта команда запускает:

```text

```

Тесты выполняются в режиме однократного запуска.

> Это одностраничное приложение на React для поиска книг по названию или ISBN. Данные поступают из публичного Book Metadata Service.

>Корневой компонент `App.jsx` отвечает за маршрутизацию между страницами. Главная страница поиска реализована в отдельном компоненте `Main.jsx`, а страница избранного — в `Favorites.jsx`.
>Логика поиска и автоподсказок вынесена в пользовательский хук `useLogic`. В нём находятся состояния поисковой строки, результатов, загрузки, ошибок и подсказок.
>
> Для получения данных используется отдельная функция `searchBooks` из `src/api/searchBooks.js`. Она формирует параметры запроса, вызывает Axios, обрабатывает HTTP-ошибки и проверяет, что API вернул массив.
>
> Во время ввода текста приложение получает автоподсказки. Для этого используется задержка 500 миллисекунд и минимальная длина запроса три символа. Пользователь может выбрать вариант или отправить собственный текст.
>
> Результаты отображаются через компонент `BookCard`. Он показывает основные сведения о книге, обрабатывает отсутствующие поля и позволяет раскрывать длинное описание.
>
> Для избранного используется отдельный пользовательский хук `useFavorite`. Он определяет идентификаторы книг, исключает дубликаты, позволяет добавлять и удалять записи и сохраняет массив в `localStorage`.
>
> Страница `Favorites.jsx` отображает сохранённые книги и позволяет искать среди них по названию, автору или ISBN. Для перехода между страницами используется React Router DOM.
>
> Интерфейс создан с помощью Material UI и дополнительных CSS-стилей. Vite используется для разработки и сборки проекта, Vitest и React Testing Library — для автоматизированного тестирования пользовательских хуков.

## 19. Ограничения текущей реализации

Ниже перечислены особенности, которые важно учитывать при работе с приложением.

### 19.1. Зависимость от внешнего API

Книги не хранятся в собственной серверной базе проекта.
Поэтому результаты поиска зависят от доступности Book Metadata Service.
Если внешний сервис недоступен, приложение не сможет получить новые результаты.

### 19.2. Лимит запросов

Внешний API имеет ограничение по количеству запросов с одного IP.
Автоподсказки уменьшают количество лишних обращений благодаря задержке 500 миллисекунд, но всё равно могут расходовать лимит API.

### 19.3. Нет собственной авторизации

В приложении не реализованы:
- Регистрация пользователей.
- Вход в аккаунт.
- Серверные профили.
- Синхронизация избранного между устройствами.

### 19.4. Избранное хранится локально

`localStorage` относится к конкретному браузеру и origin.
Поэтому список избранного:
- не синхронизируется между разными браузерами;
- не переносится автоматически на другое устройство;
- может быть удалён при очистке данных сайта;
- не доступен с другого компьютера без отдельного переноса данных.

### 19.5. Проверка ISBN

В `prepareQuery` выполняется проверка формы ISBN-10 или ISBN-13.
Однако локальная проверка контрольной суммы ISBN в приложении не реализована.
При универсальном поиске основную проверку ISBN выполняет внешний сервис.

### 19.6. Проверка структуры ответа

`searchBooks` проверяет, что API вернул массив.
Полная схема валидации каждого поля объекта книги не реализована.
При этом `BookCard` выполняет проверки основных используемых полей и отображает заглушки при отсутствии данных.

### 19.7. Обработка ошибок автоподсказок

При ошибке получения подсказок список очищается, а ошибка записывается в консоль.
Отдельное сообщение об ошибке автоподсказок пользователю не показывается.

### 19.8. Отмена запросов


Для получения автоподсказок используется `AbortController`.

Перед отправкой запроса создаётся контроллер, а его сигнал `controller.signal` передаётся в `searchBooks`, после чего в Axios.

При изменении поисковой строки предыдущий HTTP-запрос отменяется через `controller.abort()`.

Также при очистке эффекта вызывается `clearTimeout(timeoutId)`. Это позволяет отменить ожидающий таймер, если запрос ещё не был отправлен.

Таким образом, механизм учитывает две ситуации:
- Если запрос ещё не начался, очищается таймер.
- Если запрос уже выполняется, Axios получает сигнал отмены.

В `catch` проверяется, был ли запрос отменён. Такая отмена не обрабатывается как обычная ошибка API.

**Ограничение:** механизм отмены реализован для автоподсказок. Основной поиск по кнопке или клавише Enter пока не имеет отдельного механизма отмены HTTP-запроса. Во время его выполнения поле ввода и кнопка блокируются.

### 19.9. Ограниченное покрытие тестами

Тестами проверяются основные операции пользовательских хуков.
При этом не все компоненты и сценарии приложения имеют отдельные автоматизированные тесты.
Подробности приведены в разделе 16.

### 19.10. Отсутствие серверной части

Проект не включает собственный backend.
Взаимодействие с книжным сервисом происходит напрямую из клиентского приложения.
Избранное также хранится на стороне браузера.

## 20. Возможные направления развития

Этот раздел описывает идеи для дальнейшего развития. **Они не являются реализованными возможностями текущей версии.**

### 20.1. Расширение автоматизированных тестов

Можно добавить проверки:
- Различных HTTP-ошибок.
- Тайм-аута и сетевых ошибок.
- Некорректного формата ответа API.
- Задержки автоподсказок.
- Выбора подсказки.
- Работающего состояния кнопок.
- Отображения карточек.
- Раскрытия описания.
- Страницы избранного.
- Навигации между страницами.

### 20.2. Улучшение работы с запросами

В текущей реализации отмена устаревших HTTP-запросов используется для автоподсказок через `AbortController` и Axios.

В дальнейшем можно расширить этот механизм и на основной поиск, чтобы пользователь мог отменять длительные поисковые запросы.

Также можно добавить отдельные автоматизированные тесты для проверки отмены запросов, передачи `signal` и корректной обработки отменённых операций.

### 20.3. Улучшение избранного

Возможные улучшения:
- Очистка всего списка избранного.
- Сортировка сохранённых книг.
- Фильтрация по издательству.
- Фильтрация по году издания.
- Экспорт избранного в JSON.
- Перенос избранного между устройствами.

### 20.4. Улучшение интерфейса

Можно расширить возможности карточек и страницы поиска:
- Добавить дополнительные поля из API.
- Улучшить отображение длинных названий.
- Добавить сортировку результатов.
- Улучшить доступность интерфейса.
- Добавить более подробные сообщения о проблемах загрузки.

### 20.5. Развитие архитектуры

По мере роста проекта можно рассмотреть:
- Выделение дополнительных компонентов.
- Вынесение конфигурации API в переменные окружения.
- Добавление интеграционных тестов.
- Добавление E2E-тестов.
- Подключение серверного хранилища избранного, если появится авторизация.
- Настройку автоматической проверки проекта через CI.
